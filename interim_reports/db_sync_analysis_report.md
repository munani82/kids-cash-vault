# 데이터베이스 동기화 오류 원인 분석 및 실시간 영구 아키텍처 전환 보고서

## 1. 분석 개요
우리아이 디지털 금고 웹 애플리케이션에서 충전한 금액이 다른 기기에서 갱신되지 않는 현상이 보고되었습니다. 본 보고서에서는 과학적 객관성과 투명성을 바탕으로 원인을 추적하고 실제 네트워크 응답을 검증한 결과와, 이를 근본적으로 해결하기 위해 수행한 영구 실시간 동기화 아키텍처 전환 및 데이터 백업 조치를 기록합니다.

## 2. 가설 수립 및 검증 방법
• 가설: 클라우드 원격 저장소에 데이터가 정상 기록되지 않았거나 조회에 실패하여 기기 간 데이터 불일치가 발생함
• 검증 방법: 소스 코드의 데이터 흐름 분석 및 실제 클라우드 저장소 엔드포인트의 HTTP 응답 상태 직접 호출 검증

## 3. 검증 결과
1. 클라우드 데이터베이스 엔드포인트 만료 확인
웹 서비스 백엔드 프록시에서 사용 중인 외부 저장소 주소로 직접 HTTP 요청을 전송하여 상태를 확인한 결과, 저장소가 이미 만료되어 404 오류(Blob not found)를 반환하고 있었습니다.

2. 기기 간 데이터 불일치 메커니즘
• 금액 충전 기기: 사용자 액션 발생 시 로컬 저장소(localStorage)에 먼저 데이터를 즉시 기록하므로 해당 화면에서는 정상적으로 충전된 것처럼 보입니다. 그러나 이후 백엔드로 전송하는 클라우드 동기화 요청은 저장소 만료로 인해 실패합니다.
• 다른 기기: 페이지 접속 시 클라우드 저장소에서 최신 데이터를 가져오지 못하므로 해당 기기에 과거에 남아있던 로컬 저장소 값만 계속 표시됩니다.

## 4. 영구 실시간 동기화 아키텍처 전환 조치
1. 외부 임시 목업 저장소 제거
일정 기간 후 데이터가 소멸되는 외부 임시 JSON 저장소 방식을 완전히 배제하였습니다.

2. 파이어베이스 실시간 데이터베이스(Firebase Realtime Database) 전환
• 웹소켓 기반 0초 양방향 실시간 동기화 리스너(onValue)를 구현하여, 한 기기에서 충전 또는 출금 발생 시 모든 연결된 기기에 즉각 자동 반영되도록 구성하였습니다.
• 데이터 변경 시 영구 클라우드 데이터베이스에 직접 저장(set)하여 데이터 영구 보존성을 확보하였습니다.
• 로컬 스토리지 즉시 캐시 전략을 병행하여 네트워크 지연 시에도 화면 깜빡임 없이 즉각 반응하도록 안정성을 보장하였습니다.

3. 환경 변수 기반 설정 템플릿 제공
보안 및 유연한 배포 환경 지원을 위해 `.env.example` 파일을 구성하여 Vercel 및 로컬 개발 환경에서 파이어베이스 접속 키를 손쉽게 주입할 수 있도록 개선하였습니다.

## 5. 기존 데이터 백업 및 코드 복원 주입
1. 원시 백업 데이터 보존
소율(400,000원) 및 소원(100원 및 초기 입금 내역)의 기존 원시 데이터를 상대 경로 `primary_data/vault_original_data_backup.json`에 안전하게 영구 저장하였습니다.

2. 소스 코드 기본값에 백업 데이터 즉시 탑재
`src/services/firebase.js`의 `DEFAULT_VAULT_DATA`에 백업된 소율 400,000원, 소원 100원 및 입출금 기록을 직접 탑재하여, 데이터베이스 연결 초기화나 로컬 구동 시에도 금액이 0원으로 초기화되지 않고 안전하게 유지되도록 조치하였습니다.

3. 빌드 안정성 검증
프로덕션 빌드 테스트를 수행하여 번들링이 정상 완료됨을 확인하였습니다.
