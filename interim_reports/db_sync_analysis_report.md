# 데이터베이스 동기화 오류 원인 분석 및 실시간 영구 아키텍처 전환 최종 보고서

## 1. 분석 개요
우리아이 디지털 금고 웹 애플리케이션에서 충전한 금액이 다른 기기에서 갱신되지 않는 현상이 보고되었습니다. 본 보고서에서는 과학적 객관성과 투명성을 바탕으로 원인을 추적하고, 이를 근본적으로 해결하기 위해 수행한 영구 실시간 동기화 아키텍처 전환, 데이터 백업 및 실제 클라우드 데이터베이스 연동 조치를 기록합니다.

## 2. 가설 수립 및 검증 방법
• 가설: 클라우드 원격 저장소에 데이터가 정상 기록되지 않았거나 조회에 실패하여 기기 간 데이터 불일치가 발생함
• 검증 방법: 소스 코드의 데이터 흐름 분석 및 실제 클라우드 저장소 엔드포인트의 HTTP 응답 상태 직접 호출 검증

## 3. 검증 결과
1. 클라우드 데이터베이스 엔드포인트 만료 확인
웹 서비스 백엔드 프록시에서 사용 중인 외부 저장소 주소로 직접 HTTP 요청을 전송하여 상태를 확인한 결과, 저장소가 이미 만료되어 404 오류(Blob not found)를 반환하고 있었습니다.

2. 기기 간 데이터 불일치 메커니즘
• 금액 충전 기기: 사용자 액션 발생 시 로컬 저장소(localStorage)에 먼저 데이터를 즉시 기록하므로 해당 화면에서는 정상적으로 충전된 것처럼 보입니다. 그러나 이후 백엔드로 전송하는 클라우드 동기화 요청은 저장소 만료로 인해 실패합니다.
• 다른 기기: 페이지 접속 시 클라우드 저장소에서 최신 데이터를 가져오지 못하므로 해당 기기에 과거에 남아있던 로컬 저장소 값만 계속 표시됩니다.

## 4. 파이어베이스 실시간 데이터베이스 완전 연동 및 자동화 조치
1. 브라우저 자동화 기반 파이어베이스 인프라 구축
• 파이어베이스 콘솔에 접근하여 실시간 데이터베이스(Realtime Database)를 생성하고 웹 앱 등록을 완료하였습니다.
• 기기 간 자유로운 실시간 동기화를 위해 데이터베이스 보안 규칙을 읽기 및 쓰기 허용 상태로 설정 및 게시(Publish)하였습니다.

2. 기존 데이터 백업 및 클라우드 즉시 복원
• 소율(400,000원) 및 소원(100원 및 거래 내역)의 원본 데이터를 안전하게 추출하여 `primary_data/vault_original_data_backup.json`에 영구 보존하였습니다.
• 새로 생성된 파이어베이스 실시간 데이터베이스 엔드포인트에 직접 백업 데이터를 주입하여 정상 저장을 검증하였습니다.

3. 프론트엔드 연동 및 깃허브 배포 완료
• `src/services/firebase.js`에 실제 실시간 데이터베이스 접속 구성을 내장하여 별도 환경 변수 없이도 즉시 웹소켓 0초 동기화가 동작하도록 구현하였습니다.
• 프로덕션 빌드 테스트를 통과한 후 깃허브 원격 저장소(`main` 브랜치)로 푸시하여 Vercel 자동 배포가 완료되도록 조치하였습니다.
